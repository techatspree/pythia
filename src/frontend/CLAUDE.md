# Frontend (`src/frontend`) — SvelteKit 5

Loaded when working under `src/frontend/`. The always-loaded hard rules live in the root `CLAUDE.md`; this file is the detail behind them.

SvelteKit 5 (runes) + TypeScript + Tailwind 4, Vite, adapter-static (SPA).

## UI primitives (`$lib/ui/`)

`$lib/ui/Button.svelte` and `$lib/ui/Card.svelte` are the **single definition** of those two shapes (task-149). **Never retype their utility strings** — before this the primary-button classes were retyped at 24 sites across 17 files and the brand hover shade was an unnamed literal at 38, which is precisely how the session UI drifted out of style (task-148) with nothing failing to signal it.

`Button` takes `variant` (`primary` | `secondary` | `ghost` | `danger`), `size` (`md` | `sm` | `xs`) and an optional `href` — with `href` it renders an `<a>` styled identically, for the links that look like buttons ("compare versions", "start estimation session"). Two details are load-bearing: it forwards `{...rest}` so `data-testid`, `disabled`, `title` and `aria-*` reach the real element (the Playwright suite selects on those, and a version that drops rest props type-checks fine then fails e2e broadly); and it exposes `bind:element` because three modal dialogs focus their cancel/reload button on open — `bind:this` on a component yields the component instance, not the DOM node.

`Card` is `border rounded-lg overflow-hidden` plus the brand-green header strip: `<Card title="…">` for a titled card, `<Card>` for an untitled status card, and `<Card {header} padded={false}>` when the caller owns both strip and body. The four collapsible editor panels (`ParametersPanel` and siblings) deliberately still hand-roll their shell — their strip is a toggle `<button>` with a chevron and their body is `{#if open}`-gated, so wrapping them in `Card` would add indirection for one class string. Adopting them is a follow-up, not an oversight.

**Arbitrary colour values are banned and enforced.** `scripts/check-design-tokens.mjs` fails `:frontend:check` on any `-[#rrggbb]` in `src/`. Add a token to the `@theme` block in `src/app.css` and use it. This gate is deliberately *not* informational, unlike ESLint/detekt here. `src/lib/assets/logo.svg` is exempt (SVG `fill`/`stroke` cannot reference a Tailwind class) and `.svg` is excluded from the scan.

`$lib/ui/Select.svelte` is the single definition of a **form** select (task-151). A native `<select>` ignores most of the app's field classes — the browser paints its own arrow and control height — so beside an `<input>` with identical classes it reads as a different, heavier control, and differently again per platform. The primitive adds `appearance-none` plus its own chevron (`pointer-events-none`, or it swallows the click), the standard focus ring, and greys the text while the value is `''` so a placeholder reads as empty. `{...rest}` forwarding is load-bearing here too.

**Only three selects use it, and the others must not.** The app's nine `<select>`s serve three different roles: the three FORM selects (`sessions/+page.svelte` ×2, `CreateEstimationDialog`), five **in-cell editors** (`EstimationGrid` ×2, `AdditionalCostsPanel` ×2, bucket `EditorModule`) that are deliberately `bg-transparent` and borderless because they sit inside a grid cell where a bordered box would be wrong, and one **chrome** select (`UserMenu`'s language switcher). Do not "finish the job" by converting the last six.

`Field` (the remaining duplicated text inputs) and `Badge` are known follow-ups.

## Logging

Import `log` from `$lib/log.ts` (a configured `loglevel` instance — `debug` under `import.meta.env.DEV`, else `warn`). **Never write bare `console.*`.** The error-surfacing rule below still holds: a `catch` must surface failure via `ErrorBanner` — `log.error(...)` is *in addition to*, not instead of, user-facing surfacing.

## HTTP: `apiFetch` only

Talks to the backend via `apiFetch` (`$lib/api/fetch.ts`), a thin `fetch` wrapper that attaches the active auth provider's `Authorization` header; request/response types are generated from the backend OpenAPI via openapi-typescript into `$lib/api/schema.d.ts`. Raw `fetch(...)` is banned by ESLint (`no-restricted-syntax`) in favour of `apiFetch` (task-090).

**File downloads are no exception**: a plain `<a href="/api/…" download>` is banned too, because browser navigation carries no `Authorization` header — the strict dev module then answers `401` and the browser silently SAVES THAT JSON ERROR BODY as the "export" file (the xlsx/csv export menu shipped that way and produced no spreadsheet at all). Every download goes `apiFetch` → `assertOk` → `res.blob()` → the shared `downloadResponse(blob, contentDisposition, fallbackName)` in `$lib/api/download.ts`, which reads the filename out of the `Content-Disposition` header and clicks a temporary object-URL anchor; both the version editor's xlsx/csv export and the estimation detail page's Merlin export use it, and `e2e/export.test.ts` pins that the downloaded bytes are a real zip/CSV rather than a JSON error body.

## Error surfacing rule

Every `try`/`catch` MUST surface failure to the user via the shared `ErrorBanner` component (`src/frontend/src/lib/components/ErrorBanner.svelte`). A `catch` that returns a fallback while only logging to `console.error` is **not** acceptable — that is the bug pattern that hid the Kotlin/JS stack-overflow as blank `—` cells in the grid. The single seam that turns a failed HTTP `Response` into a user-facing message is `src/frontend/src/lib/api/errors.ts` (`assertOk(res, fallback)` / `messageForStatus`, task-093) — it prefers the backend error body's `message`, else a status-specific default (401/403 → fixed authorization strings). Call sites do `await assertOk(res, '<fallback>')` after `apiFetch`, then keep their `try`/`catch` → `log.error(...)` + `bannerMessage`; do NOT scatter raw `if (!res.ok) throw new Error('…')` status checks across pages.

The request seam `apiFetch` itself **throws** `Authentication failed: <reason>` (with the original error as `cause`) when the auth provider cannot produce a token (e.g. MSAL silent-token acquisition fails after an Entra app-registration change) — it does NOT fall through and send an anonymous request that would only 401 with a misleading "session expired". A `null` header (not signed in) is not a failure: the request goes out anonymous and the backend 401 drives the sign-in message.

A genuine **connection loss** (task-136) — `apiFetch`'s `fetch` rejecting, its ~10s `AbortController` timeout firing, or a `502/503/504` — is escalated (not to the banner) via the global `ConnectionStore` (`$lib/stores/connection.svelte.ts`, `connection.reportLost(...)`), which **blocks the whole app** with `ConnectionLostDialog` (mounted once in the root `+layout.svelte`, overlays every route). The block stays until a heartbeat — the unauthenticated `GET /api/ping` (`PingResource`, `@PermitAll`), polled every ~3s — answers AND the user acknowledges; acknowledging does a **full page reload** (`window.location.reload()`, not `invalidateAll()`) so the unsaved (lost) edit is discarded rather than silently re-saved by a later autosave. Ordinary 4xx/5xx business errors keep the non-blocking `ErrorBanner` path; a caller-initiated `AbortController` cancel is not treated as a connection loss.

## Domain bridge (`adapter.ts`)

`src/frontend/src/lib/adapter.ts` computes the local calc map by calling into the Kotlin/JS-compiled domain (`createVersion(...).calculate()`) and then walking the result tree recursively. Its entry point is `computeEstimation(roots, params, drivers, phases, additionalCosts)` (task-139, formerly `computeCalcMap`), which returns **`{ calcMap, totals }`** from a SINGLE build+`calculate()` — the per-node map and the whole-estimation totals come off one domain round-trip, so an edit does not recompute the version twice per keystroke. The `totals` half is the domain reducer `EstimationVersion.totals()`; see the summary-panel note below. Both the wire DTOs (`EstimationVersionDto.roots`, `DraftUpdateDto.roots`) and the Kotlin/JS factories (`createVersion(roots: Array<EstimationNode>)`, `createGroup(children: Array<EstimationNode>) → EstimationGroup`, `createFixedItem`, `createTimeRelativeItem`, and `createBucketedItem(description, bucketId, isSample, optimistic, likely, pessimistic, logicalId)` for the bucket method — task-104) speak the canonical tree shape — no legacy `itemGroups` field anywhere. The `adapter.ts` calc map carries `mean` alongside `offerPT`/`cost`/`offerPrice` so the bucket editor can show each non-sample leaf's domain-derived bucket mean. If you see a stale `.d.mts` (TypeScript picks `.d.mts` for `.mjs` imports), force a full rebuild: `./gradlew :domain:clean :frontend:clean :frontend:check`. (Kotlin 2.3.x emits `domain.d.mts` directly; `prepareTypescriptArtifacts` copies it through.)

## `$bindable` two-way binding (editor components)

The version editor lets Svelte own state end-to-end. The page (`routes/estimations/[id]/versions/[versionNumber]/+page.svelte`) holds one source-of-truth `$state` per collection (`currentParameters`, `currentDrivers`, `currentPhases`, `currentAdditionalCosts`, `currentRoots`, `currentNotes`), normalised once in `loadVersion()` (roots via `normalizeRoots` from `$lib/estimationNodes`). It passes each down with `bind:` to the editor children — the four sibling panels (`ParametersPanel`, `EffortDriversPanel`, `PhasesPanel`, `AdditionalCostsPanel`) and `EstimationGrid` — which declare the data prop as `$bindable()` and **mutate it directly** (`push`/`splice`/field assignment, or reassign for wholesale replacement). There is no local snapshot, no `notify()`, and no `onchange` callback; Svelte propagates child mutations back to the page. Autosave is a single guarded `$effect` in the page: it deep-reads the editable state via `$state.snapshot(...)`, compares against a `lastSavedSnapshot` baseline set at load, and debounces a PUT only on an actual edit to a draft (never on load/reload). Do NOT reintroduce the old "snapshot prop into local `$state` + onchange" pattern. (`TreeTable`'s expand/collapse is the one exception that stays deliberately local — it is private UI state the page does not own. It holds only the rows the user has EXPLICITLY toggled (`expandedOverrides`), falling through to the caller's `defaultCollapsed(node)` rule for the rest — a live read, not a copy of the prop into `$state`.)

## Pluggable per-method editors

Per-method editor UIs are pluggable: `$lib/methods/registry.ts` maps each `EstimationMethod` to a lazy `import()` of `$lib/methods/<method>/EditorModule.svelte`; the version editor route reads the estimation's `method` and renders the resolved module as a dynamic component, while keeping autosave + undo/redo on the route (the module is a pure `$bindable` view). `registry.ts` also exports `availableMethods` (derived from the registered modules + a `methodLabels` map) which drives the method picker in `CreateEstimationDialog.svelte` (task-116) — registering a method there implies full-stack support.

PERT lives in `methods/pert/`; the bucket + sampled editor lives in `methods/bucketSampled/` (task-104): `EditorModule.svelte` renders the shared panels plus a `BucketPanel.svelte` (add/rename/delete/drag-reorder buckets, `svelte-dnd-action`) and a `TreeTable` of bucketed leaves (bucket picker → `bucketId`, sample toggle → `isSample`, a three-point editor shown only on sample rows, and a read-only derived `mean` column for non-sample rows).

Since task-132 that editor offers **two views** over the same `roots`, toggled by a segmented control (the choice persists in `localStorage` under `estimator.bucketView`; default `bucket`). They are **two projections of one model**, and their drag-and-drop meanings are deliberately disjoint: the **bucket view** renders a `$derived` synthetic tree — one row per bucket in `position` order plus a trailing `bucket:unassigned` row (which also collects leaves stranded by a deleted bucket) whose children are the *flattened* leaves of the whole tree; that unassigned row is a rescue **source only** — a drop *into* it is deliberately ignored, because the backend rejects a `BUCKETED` leaf with a null `bucketId` (`400`), so accepting it would only yield a failing autosave. A drop onto a real bucket changes **only** `bucketId` (via `onChildrenChange`, never moving anything in the real tree; ordering inside a bucket is **not persisted**, so a same-bucket reorder is a deliberate no-op). The **hierarchy view** is the real nested-group tree with `+ group` / `+ item` / `✕` row actions, where a drop restructures the tree and never touches `bucketId`. Those row actions render only on a `GROUP` row, so the view ALSO carries a **root-level `bucket.addGroupRow`** ("+ Gruppe hinzufügen") in both its footer and its empty state — without it a flat draft could never grow its first group and the view looked broken (task-150; the seeded bucket estimation was flat too, so nobody saw a group in dev). The **bucket view deliberately has no group affordance**: its rows are synthetic bucket rows, not domain groups. `e2e/bucket-hierarchy.test.ts` pins the whole loop. Bucket estimations legitimately contain `GROUP` nodes — the Merlin importer (task-131) creates exactly that shape — which the old flat editor could not display at all.

Synthetic bucket rows are **not** domain groups: they carry a synthetic `logicalId` (`bucket:<id>`) only to satisfy `TreeTable.getId`, and their numbers are a display-only **sum** of their leaves' already-computed `calcMap` entries; all bucket math stays in the domain's `BucketMethodModule`. The per-row bucket `<select>` remains in both views so re-bucketing stays keyboard-reachable. Since task-134 the bucket view opens with all **bucket rows collapsed** — expressed as `TreeTable.defaultCollapsed={isBucketRow}` (its first consumer), so every bucket is visible at once and a cross-bucket drag is a short movement. `defaultCollapsed` is a **rule, not a seed**: it is consulted for every row the user has not toggled, so a bucket added after mount starts collapsed too (it was seeded once into local state before, which both made a later-added bucket render expanded and tripped Svelte's `state_referenced_locally` warning — do not go back to copying the prop into `$state`). That collapse state is transient: it is not persisted (unlike the view choice in `localStorage`), and toggling to the hierarchy view and back remounts the table, dropping the user's overrides so the rule re-collapses the rows. The hierarchy view stays fully expanded — there the nesting is the information. The route owns a `currentBuckets` `$state` (read from the estimation-detail `buckets`, seeded XS/S/M/L/XL for a fresh draft) and PUTs it as `DraftUpdateDto.buckets`. The chosen estimation method is surfaced in the project-detail estimations table, the estimation-detail header, and the version editor header via `$lib/methods/labels.ts::formatMethodLabel` (task-118).

## Whole-estimation totals (`EstimationSummaryPanel`)

The version editor route renders `src/frontend/src/lib/components/EstimationSummaryPanel.svelte` **above** the method module (task-139), so every method shows one total for the whole estimate — the bucket+sampled editor aggregates only per bucket and previously had no estimate-wide number at all. The panel is on the ROUTE, not in a method module, so the two methods cannot drift; it renders for drafts and submitted versions alike and is deliberately **not** `position: sticky` (the editors below it are `svelte-dnd-action` drop zones whose geometry the library measures at drag start).

The figures are **computed by the domain**, never summed in Svelte: `EstimationTotals` + `EstimationVersion.totals()` in `src/domain/.../model/EstimationTotals.kt`. `totals()` is a **member** function, not an extension — `@JsExport` does not export extension functions, so an extension would compile, pass `:domain:build`, and then be missing from `domain.d.mts`. It must be called on the result of `calculate()` (a leaf's `cost`/`offerPrice` derive from the `CalculationParameters` that `calculate()` stamps on), and it reads `offerPT` off the already-computed `totalEffort` rather than re-summing. `totalOfferPrice` follows the customer's canonical formula — `(developmentCost + additionalOneTime + additionalRecurring) × (1 + salesSurcharge)`, the one `ExcelExporter.writePhases` applies per phase — while the separate `developmentOfferPrice` is the tree's own price EXCLUDING additional costs, which is what a column of per-leaf offer prices sums to. A RECURRING additional cost with a null phase contributes 0 and is counted in `recurringWithoutPhase`, which the panel surfaces as a warning line rather than silently absorbing (the task-138 lesson).

`EstimationGrid`'s footer reads those same totals. It used to reduce `Array.from(calcMap.values())`, but that map holds an entry for **every node including GROUPs** and a group accumulates its whole subtree — so the PERT footer **double-counted every grouped estimation**. Its `min`/`expected`/`max` sums stay leaf-based via `allLeaves(roots)` (those were always correct). `e2e/summary-panel.test.ts` pins both halves.

## Undo/redo store (`UndoStore`)

Persistent undo/redo (task-076) is a thin client over the backend endpoints, wired into the version editor page. `src/frontend/src/lib/stores/undo.svelte.ts` exports the `UndoStore` runes class (`history`/`loading`/`conflict`/`error` `$state`, `canUndo`/`canRedo` `$derived`, and `refresh`/`undo`/`redo`/`clearConflict`). It owns **only** the mutation-log view — NOT the draft state: after a successful `undo`/`redo` it calls the owner-supplied `onResult(version)` hook, and the page replaces its draft `$state` through the same `applyVersionData` normalize path used on load (which also resets the autosave baseline, so re-hydrating from an undo never triggers a spurious PUT). The page calls `store.refresh()` after the initial draft load and after every successful autosave PUT, and mirrors `store.error` into its existing `bannerMessage`/`ErrorBanner`. A 409 is parsed into `conflict` (no throw). `src/frontend/src/lib/stores/undoKeyboard.svelte.ts` exports `installUndoShortcuts(store)` (Ctrl/Cmd+Z = undo, Ctrl/Cmd+Shift+Z / Ctrl+Y = redo), installed via an `$effect`; it defers to native input undo unless the target sits inside the grid's `data-undo-aware="true"` surface (set on `EstimationGrid`'s container). All HTTP goes through `apiFetch`; DTOs are the **generated** `components['schemas']` types from `$lib/api/schema` — this store is the first consumer of the generated `schema.d.ts` (existing components still use the hand-written `$lib/api/types.ts`). The visible UI (task-077) lives on the version editor page: Rückgängig/Wiederholen toolbar buttons (disabled via `canUndo`/`canRedo`, tooltips drawn from `history`), a collapsible `UndoHistoryPanel` rendered as a section directly under the toolbar (above the version title, task-109 — it used to sit below the editor grid, which put it off-screen and needed a `scrollIntoView` workaround), and a `UndoConflictDialog` shown whenever `conflict` is non-null (its "Aktuellen Stand neu laden" action re-runs the page's `loadVersion` + `refresh` + `clearConflict`; 409s go to this dialog, never to `ErrorBanner`).

## Generic `TreeTable` component

`src/frontend/src/lib/components/treetable/TreeTable.svelte` is a domain-agnostic, OmniOutliner-style tree-table component generic over a node type `T`. Callers supply `getId` / `getChildren` + a column array whose `cell` snippets render per-row content (branching on the node's data discriminator to draw editors on leaves and aggregates on group rows). The component owns indent guide lines, expand/collapse, nested per-group `svelte-dnd-action` dndzones, cycle protection (deep-clone snapshot + microtask-deferred structural-anomaly check: duplicate IDs OR lost IDs), and the header / optional footer / optional per-row actions slot. The zones use `useCursorForDetection`, so a children zone with **no** children must keep a `min-h-8`: an empty zone otherwise collapses to 0 px and can never be hovered, which silently made an empty group — and every freshly created (hence empty) bucket in the bucket view — impossible to drop into. A group's children zone is also rendered **when the row is collapsed** (task-134), because `svelte-dnd-action` captures its drop zones **at drag start** — `watchDraggedElement` instruments exactly the zones registered at that moment — so a zone that first appears mid-drag can never receive the drop. (That is why "spring-loading" a collapsed row on hover was tried, measured and rejected.) The collapsed row's descendants therefore stay in the DOM and are collapsed visually instead, via `h-0 overflow-hidden invisible` on the row wrapper — `visibility: hidden` rather than `display: none` on purpose: it keeps a layout box for the library's geometry while removing the subtree from the tab order. Because `items` and the DOM children stay one-to-one, `applyChildren` keeps its replace semantics and the cycle protection is unchanged. A collapsed zone claims its `min-h-8` strip only while a drag is in flight (`dragActive`, derived from the existing `draggedSubtreeIds`). The `roots` prop is `$bindable` so callers can run imperative add/delete mutations that the component reflects immediately. Optional `rowAttrs` and `childrenZoneAttrs` hooks let callers attach extra attributes (e.g. legacy testids, per-group aria-labels) to outer row wrappers and to children dndzones. Types live in `treetable/types.ts`.

**Production consumer**: `src/frontend/src/lib/components/EstimationGrid.svelte` (the estimation editor — composes TreeTable with 11 column snippets, calc-map aggregation, keyboard cell-nav, and the `+ group` / `+ item` / `✕` row actions). **Regression harness**: `src/frontend/src/routes/dev/tree-table-demo/+page.svelte` (a static product-catalog fixture exercising the generic API, accessible at `/dev/tree-table-demo`).

Columns may opt in to auto-collapse on narrow containers via `collapsible: true`; the threshold is configurable per-TreeTable through `collapseBreakpointPx` (default 900 px). The outer wrapper is horizontally scrollable, so content that exceeds the viewport stays reachable even when no columns collapse further. Per-row action buttons (the `rowActions` snippet) live in a dedicated trailing column by default; callers can pass `actionsPlacement="treeColumn"` to inline the actions inside the tree column instead — EstimationGrid uses this so its `+ group` / `+ item` / `✕` controls sit directly after the row title rather than off to the right past every value column.

**A header label never paints outside its own column** (task-140): the header row (`data-testid="tt-header"`) is deliberately **normal-case** — `uppercase tracking-wide` cost ~20-25 % extra width for no legibility gain, which is what pushed labels out of their fixed tracks — and every header cell carries `min-w-0 overflow-hidden whitespace-normal break-words leading-tight`, with `items-end` on the row so a wrapped two-line label stays on the baseline of its single-line neighbours. Without that, a **single long word cannot wrap** and simply overflows its grid item, painting over the neighbouring header (DE "PESSIMISTISCH" needs ~108 px in a 6rem track's ~80 px content box). `overflow-hidden` is deliberately NOT applied to the data cells — they hold focusable `<input>`/`<select>` elements whose focus rings it would clip. `e2e/treetable-header-fit.test.ts` guards this by measuring `scrollWidth <= clientWidth` on every header cell across the PERT grid and both bucket-editor views, **in both locales** (the defect is translation-dependent, so a German-only check would let an English regression through); its English case runs under a dedicated `dev-estimator` user because the language preference is persisted per user and specs share one backend.

## The one app header (`AppHeader`)

`src/frontend/src/lib/components/AppHeader.svelte` is the **single** top navigation, rendered by the root `+layout.svelte` on **every** route (task-141). Before it there were two divergent top bars — the root layout's inline header, hidden for `/sessions` via an `isSessionRoute` guard, and the session group's own chrome — so a user in a session room saw unfamiliar chrome with no recognisable way out. **Do not duplicate header markup into a route layout again**; add a destination to the component's `items` array instead. It renders the brand lockup (mark + wordmark, linking home), the horizontal menu, and `UserMenu`, above the brand gradient hairline; when `account` is `null` (the auth gate is showing the login dialog) only the lockup and hairline render.

The menu is a **flat row of `<a>`s inside a `<nav>`** — deliberately not a `<ul>`/`<li>` list, because `e2e/undo.test.ts` asserts a page-global `ul li` count of 0 and a nav list silently breaks it. A destination is active when the path equals its href **or starts with `href + '/'`**, so `/projects/{id}` keeps "Projects" marked and a room keeps "Sessions"; the active item gets `aria-current="page"` plus brand-green text and bottom border. `/estimations/**` sits under neither item and matches none — that is correct, not a gap. Each item's href comes from `resolve()` in the `items` array, which the `svelte/no-navigation-without-resolve` ESLint rule cannot follow, so the loop carries the same scoped `eslint-disable-next-line` the two computed-href call sites already use (`estimations/[id]/+page.svelte`, `VersionList.svelte`) — and the `<a href={item.href}` must stay on ONE line or the suppression lands on the wrong line. The per-page contextual back links (`project.pageBack`, `estimation.pageBack`, `compare.back`, `editor.back`, `session.summary.backToDraft`, `session.room.backToEstimation`) are unaffected: the menu is global navigation, they are local. `e2e/navigation.test.ts` pins the header on every route including a seeded session room, the active-item marking, and the way back out.

## i18n (UI strings)

Frontend UI strings live in `svelte-i18n` JSON catalogs under `src/frontend/src/lib/i18n/` — **never** inline string literals in components (phase-16, task-124). `src/lib/i18n/index.ts` registers the `de` locale from `de.json`, calls `init({ fallbackLocale: 'de', initialLocale: 'de' })`, and exports `setUserLanguage(lang: SupportedLanguage)` (it drives the `locale` store off the domain enum's `code` — the same `SupportedLanguage` shared with the backend). The init runs as an import side effect; `src/routes/+layout.ts` imports it and its `load` does `await waitLocale()` so first paint never flashes a raw key (the route is `ssr = false`). Components render via the reactive `$_('key')` store (`import { _ } from 'svelte-i18n'`), with interpolation `$_('key', { values: { … } })` and ICU plural/select supported; a module-context helper (e.g. `UndoHistoryPanel.relativeTime`) reads it imperatively with `get(_)`. Keys are dot-separated and component-scoped (`panel.parameters.title`, `history.conflict.body`, `editor.undoTooltip`). task-124 was a DE lift-and-shift (catalog holds the current verbatim text — mostly English today with German pockets — so there was no visible change). task-125 added `en.json` (mirrors `de.json` key-for-key), registered `'en'`, and a **language switcher** in `UserMenu.svelte` — a DE/EN `<select>` that `PUT`s `/api/auth/me/language` via `apiFetch` then `setUserLanguage(...)`, surfacing failures through a local `ErrorBanner` + `log.error`. On startup the root layout reads the account's persisted `language` (from `GET /api/auth/me`; task-123's `CurrentUserDto.language`) and applies it once the account resolves, **falling back to `'de'`**. Both providers populate `AuthAccount.language` from the backend: Entra via `fetchCurrentUserAccount`, and the **dev** provider's `loadAccount()` also fetches `GET /api/auth/me` for the `language` only (roles/displayName stay client-side per task-120), so a language switch **persists across a dev reload** too (task-127). Its e2e (`e2e/language.test.ts`) proves the reload-persistence under a dedicated `dev-estimator` user; `playwright.config.ts` pins `locale: 'de-DE'` so Accept-Language seeds fresh dev users German. Code↔enum mapping is `SupportedLanguage.values().find((v) => v.code === code)` (the domain `fromCode` helper is JVM-only, not `@JsExport`ed). The generic `treetable/TreeTable.svelte` and the `dev/tree-table-demo` fixture are intentionally left un-internationalised (generic / dev-only).

All number/currency/date **formatting** goes through the single leaf module `src/frontend/src/lib/format.ts` (phase-16, task-126): `formatNumber` / `formatFixed(value, locale, fractionDigits)` / `formatCurrency` / `formatDate`, built on `Intl.NumberFormat` / `Intl.DateTimeFormat`. It is pure — the active locale is a **parameter** (callers pass `$locale ?? DEFAULT_LOCALE`, so the module never imports the i18n store and stays a leaf dependency; use `$locale` in markup, `get(locale)` in plain functions). **Never** call `.toFixed()`, `toLocale*()`, or hardcode a `de-DE` locale in a component — those were all migrated to the helper so English users see English grouping/date order. Currency is **always EUR/€** regardless of locale (the tool is EUR-only); cost/price columns that already carry a `(EUR)` header use `formatNumber`/`formatFixed` (grouping only), not `formatCurrency`. The `dev/tree-table-demo` fixture is exempt.

## Brand assets

The product mark is the **single asset** `src/frontend/src/lib/assets/logo.svg` (phase-17, task-130; crystal-ball concept adopted later from `planning/inputdata/LogoSuggestion.png`): a rounded-square chip filled with the `--gradient-brand` green carrying a white **forecasting crystal ball** on a tiered pedestal — a translucent glass sphere (bright rim + top-left shine) holding three rising bars and a dotted lead-in that becomes a solid trend arrow taking off up-right (the dots echo the earlier three-point/PERT motif). The bars are faint, the arrow and rim are chunky, and fine detail is kept minimal because it dissolves in the 16 px favicon. Components import it (`import logo from '$lib/assets/logo.svg'`); it is the header lockup mark and the dev-login dialog mark, and it drives `<link rel="icon" type="image/svg+xml">` (the session-room chrome that carried a third copy was deleted by task-141). **The wordmark is deliberately NOT baked into the SVG** — text inside an `<img>`-referenced SVG cannot use the Google-hosted Poppins webfont, so the lockup is `mark <img>` + HTML text styled with `font-heading`. Beside that wordmark the mark is decorative (`alt="" aria-hidden="true"`) so a screen reader does not announce the name twice; standalone uses (the dev-login dialog) carry a real `alt`. The raster app icons and manifest in `src/frontend/static/` (`icon-{16,32,48,180,192,512}.png`, `favicon-32.png`, `favicon.ico`, `apple-touch-icon.png`, `apple-touch-icon-precomposed.png`, `site.webmanifest`) are **generated** from the SVG by `npm run gen:icons` (`src/frontend/scripts/generate-icons.mjs`, which rasterises via Playwright's bundled Chromium — do NOT add `sharp` or any other image dependency) and committed, so a plain `npm run build` never needs a browser. Re-run `gen:icons` whenever `logo.svg` changes. `favicon.ico` is packed by the script itself (an ICO container wrapping the 16/32/48 PNGs — no encoder dependency), and `favicon.ico` / `apple-touch-icon-precomposed.png` exist because browsers and iOS probe those well-known paths on their own regardless of the `<link>` tags. Brand strings live under the `brand.*` i18n keys (`brand.name`, `brand.logoAlt`) like every other UI string. The legacy third-party corporate mark that predated it was removed by task-130 and must not be reintroduced.

## System settings (name + custom stylesheet)

The installation's display name and optional stylesheet (task-146) come from `GET /api/system`, which is unauthenticated so the login screen can be branded before an account exists. `$lib/stores/system.svelte.ts` loads it once from the root layout; the load is deliberately **not** awaited into the auth path and its failure only `log.error`s — branding must never gate rendering.

The name is a **fallback chain, not a replacement**: `system.displayName ?? $_('brand.name')` in `AppHeader.svelte`, and `?? $_('brand.logoAlt')` for the standalone mark in `DevLoginDialog.svelte`. Keep the `brand.*` keys in both catalogs.

The custom stylesheet is delivered as `<link rel="stylesheet" href="/api/system/css">` in the root layout's `<svelte:head>`, LAST so it overrides `app.css` (which defines `--color-brand-green`, `--color-brand-green-light`, `--gradient-brand`). It is deliberately **not** injected as `<style>{cssText}</style>`: a `</style>` sequence in an uploaded file would close the element early and inject arbitrary markup. The `<link>` carries no `Authorization` header, which is exactly why the endpoint is `@PermitAll` — this is NOT a violation of the "downloads go through `apiFetch`" rule, which targets authenticated downloads that silently save a 401 body. Because the stylesheet lives in the document head, the admin page does a full `window.location.reload()` after an upload or removal rather than trying to swap it in place.
