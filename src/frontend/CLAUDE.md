## Logging

Import `log` from `$lib/log.ts` (a configured `loglevel` instance — `debug` under `import.meta.env.DEV`, else `warn`). **Never write bare `console.*`.** The error-surfacing rule below still holds: a `catch` must surface failure via `ErrorBanner` — `log.error(...)` is *in addition to*, not instead of, user-facing surfacing.

## Container image (`:frontend:imageBuild`, task-195)

The image is assembled by **jib-core**, used as a library in `src/frontend/build.gradle.kts`, the way Quarkus/Jib builds the backend's. There is no Dockerfile: no Docker daemon to build or push, no second `npm run build` inside a container (the image takes `build/` from Gradle's `npmBuild`), and a **digest-pinned** nginx base (`frontendBaseImage`). Upgrading nginx is a deliberate edit of that line. A push builds `linux/amd64` + `linux/arm64` as one index (task-196), and a daemon load builds `linux/amd64` only, because a daemon load takes a single image, not an index. That is a fixed platform, not the host's, so the image never depends on the machine that built it; the backend follows the same rule.

Layers: `nginx.conf` → `/etc/nginx/templates/default.conf.template`, then every file under `build/` except `config.json` (see `src/lib/config/CLAUDE.md`) → `/usr/share/nginx/html`, in sorted order. **Never set an entrypoint or CMD**: inheriting nginx's `/docker-entrypoint.sh` is what renders the template (`${NGINX_LOCAL_RESOLVERS}`) and runs the local-resolvers script, because `NGINX_ENTRYPOINT_LOCAL_RESOLVERS=1`. Never take a creation time from the clock either. Jib's fixed epoch keeps the build independent of *when* it runs, and CI asserts both the digest pin and the absence of `Instant.now`/`setCreationTime`.

Targets are Gradle properties without dots, so each can also come from `ORG_GRADLE_PROJECT_<name>`:

| property | default | meaning |
|---|---|---|
| `frontendImagePush` | `false` | `false`: load into the local Docker daemon, `linux/amd64` only (CI `images`). `true`: push a `linux/amd64` + `linux/arm64` index to a registry with no Docker at all (minikube's registry addon, real registries). |
| `frontendImageRegistry` | — | host plus optional path prefix; **required** when pushing |
| `frontendImageTag` | `project.version` | the tag |
| `frontendImageUsername` / `frontendImagePassword` | — | push credentials; otherwise `~/.docker/config.json` and the well-known credential helpers |
| `frontendImageSourceUrl` | — | when set, adds the OCI `org.opencontainers.image.source` label. Only the release `publish` job sets it (task-199), so GHCR links the package to the repository; unset, the image is unchanged |

Every build also writes the image's digest to the ROOT `build/frontend-image/jib-image.digest` — for a push, the multi-arch index's digest, which `publish` cross-checks against GHCR. Not under `src/frontend/build/`: that directory IS the SPA the image is made from, so a file there would ship in the next image. **That holds for every Gradle task, not just this one**: an up-to-date marker or a report written under `layout.buildDirectory` of `:frontend` lands in the SPA (and `vite build` wipes it, so the task never stays up to date). Use `rootProject.layout.buildDirectory`, as `lintOpenApi` and `checkOssCompliance` do — both first made exactly this mistake.

The reference is `[<registry>/]pythia/pythia-frontend:<tag>`. The k8s base, the overlays' `images:` rewrite and `minikube-deploy.sh` depend on that name. The task is never up to date and not cacheable, because the image is a side effect. Plain HTTP is allowed **only** for a `localhost`/`127.0.0.1` registry (a throwaway `registry:2` in a test). jib-core has no such exception of its own, and a real registry must stay HTTPS.

In CI (`CI` set), `npmInstall` runs `npm ci`, so the shipped bundle is built from exactly `package-lock.json`, as the old Dockerfile's `npm ci` guaranteed. Locally it stays `npm install`.

## HTTP: `apiFetch` only

Talks to the backend via `apiFetch` (`$lib/api/fetch.ts`), a thin `fetch` wrapper that attaches the active auth provider's `Authorization` header; request/response types are generated from the backend OpenAPI via openapi-typescript into `$lib/api/schema.d.ts`. Raw `fetch(...)` is banned by ESLint (`no-restricted-syntax`) in favour of `apiFetch` (task-090).

**File downloads are no exception**: a plain `<a href="/api/…" download>` is banned too, because browser navigation carries no `Authorization` header — the strict dev module then answers `401` and the browser silently SAVES THAT JSON ERROR BODY as the "export" file (the xlsx/csv export menu shipped that way and produced no spreadsheet at all). Every download goes `apiFetch` → `assertOk` → `res.blob()` → the shared `downloadResponse(blob, contentDisposition, fallbackName)` in `$lib/api/download.ts`, which reads the filename out of the `Content-Disposition` header and clicks a temporary object-URL anchor; both the version editor's xlsx/csv export and the estimation detail page's Merlin export use it, and `e2e/export.test.ts` pins that the downloaded bytes are a real zip/CSV rather than a JSON error body.

## Error surfacing rule

Every `try`/`catch` MUST surface failure to the user via the shared `ErrorBanner` component (`src/frontend/src/lib/components/ErrorBanner.svelte`). A `catch` that returns a fallback while only logging to `console.error` is **not** acceptable — that is the bug pattern that hid the Kotlin/JS stack-overflow as blank `—` cells in the grid. The single seam that turns a failed HTTP `Response` into a user-facing message is `src/frontend/src/lib/api/errors.ts` (`assertOk(res, fallback)` / `messageForStatus`, task-093) — it prefers the backend error body's `message`, else a status-specific default (401/403 → fixed authorization strings). Call sites do `await assertOk(res, '<fallback>')` after `apiFetch`, then keep their `try`/`catch` → `log.error(...)` + `bannerMessage`; do NOT scatter raw `if (!res.ok) throw new Error('…')` status checks across pages.

The request seam `apiFetch` itself **throws** `Authentication failed: <reason>` (with the original error as `cause`) when the auth provider cannot produce a token (e.g. MSAL silent-token acquisition fails after an Entra app-registration change) — it does NOT fall through and send an anonymous request that would only 401 with a misleading "session expired". A `null` header (not signed in) is not a failure: the request goes out anonymous and the backend 401 drives the sign-in message.

A genuine **connection loss** (task-136) — `apiFetch`'s `fetch` rejecting, its ~10s `AbortController` timeout firing, or a `502/503/504` — is escalated (not to the banner) via the global `ConnectionStore` (`$lib/stores/connection.svelte.ts`, `connection.reportLost(...)`), which **blocks the whole app** with `ConnectionLostDialog` (mounted once in the root `+layout.svelte`, overlays every route). The block stays until a heartbeat — the unauthenticated `GET /api/ping` (`PingResource`, `@PermitAll`), polled every ~3s — answers AND the user acknowledges; acknowledging does a **full page reload** (`window.location.reload()`, not `invalidateAll()`) so the unsaved (lost) edit is discarded rather than silently re-saved by a later autosave. Ordinary 4xx/5xx business errors keep the non-blocking `ErrorBanner` path; a caller-initiated `AbortController` cancel is not treated as a connection loss.

## Domain bridge (`adapter.ts`)

`src/frontend/src/lib/adapter.ts` computes the local calc map by calling into the Kotlin/JS-compiled domain (`createVersion(...).calculate()`) and then walking the result tree recursively. Its entry point is `computeEstimation(roots, params, drivers, phases, additionalCosts)` (task-139, formerly `computeCalcMap`), which returns **`{ calcMap, totals }`** from a SINGLE build+`calculate()` — the per-node map and the whole-estimation totals come off one domain round-trip, so an edit does not recompute the version twice per keystroke. The `totals` half is the domain reducer `EstimationVersion.totals()`; see the summary-panel note below. Both the wire DTOs (`EstimationVersionDto.roots`, `DraftUpdateDto.roots`) and the Kotlin/JS factories (`createVersion(roots: Array<EstimationNode>)`, `createGroup(children: Array<EstimationNode>) → EstimationGroup`, `createFixedItem`, `createTimeRelativeItem`, and `createBucketedItem(description, bucketId, isSample, optimistic, likely, pessimistic, logicalId, assumptions, phase)` for the bucket method — task-104; its last two parameters TRAIL `logicalId` rather than sitting where `createTimeRelativeItem` puts them, because `adapter.ts` calls this factory positionally and inserting them earlier would land the logicalId in `assumptions`, task-186) speak the canonical tree shape — no legacy `itemGroups` field anywhere. The `adapter.ts` calc map carries `mean` alongside `offerPT`/`cost`/`offerPrice` so the bucket editor can show each non-sample leaf's domain-derived bucket mean. If you see a stale `.d.mts` (TypeScript picks `.d.mts` for `.mjs` imports), force a full rebuild: `./gradlew :domain:clean :frontend:clean :frontend:check`. (Kotlin 2.4.10, like 2.3.x before it, emits `domain.d.mts` directly; `prepareTypescriptArtifacts` copies it through. The 2.4 upgrade changed one line of it, `KtList<E>` → `KtList<out E>`, task-198.)

## `$bindable` two-way binding (editor components)

The version editor lets Svelte own state end-to-end. The page (`routes/estimations/[id]/versions/[versionNumber]/+page.svelte`) holds one source-of-truth `$state` per collection (`currentParameters`, `currentDrivers`, `currentPhases`, `currentAdditionalCosts`, `currentRoots`, `currentNotes`), normalised once in `loadVersion()` (roots via `normalizeRoots` from `$lib/estimationNodes`). It passes each down with `bind:` to the editor children — the four sibling panels (`ParametersPanel`, `EffortDriversPanel`, `PhasesPanel`, `AdditionalCostsPanel`) and `EstimationGrid` — which declare the data prop as `$bindable()` and **mutate it directly** (`push`/`splice`/field assignment, or reassign for wholesale replacement). There is no local snapshot, no `notify()`, and no `onchange` callback; Svelte propagates child mutations back to the page. Autosave is a single guarded `$effect` in the page: it deep-reads the editable state via `$state.snapshot(...)`, compares against a `lastSavedSnapshot` baseline set at load, and debounces a PUT only on an actual edit to a draft (never on load/reload). Do NOT reintroduce the old "snapshot prop into local `$state` + onchange" pattern. (`TreeTable`'s expand/collapse is the one exception that stays deliberately local — it is private UI state the page does not own. It holds only the rows the user has EXPLICITLY toggled (`expandedOverrides`), falling through to the caller's `defaultCollapsed(node)` rule for the rest — a live read, not a copy of the prop into `$state`.)

## Whole-estimation totals (`EstimationSummaryPanel`)

The version editor route renders `src/frontend/src/lib/components/EstimationSummaryPanel.svelte` **above** the method module (task-139), so every method shows one total for the whole estimate — the bucket+sampled editor aggregates only per bucket and previously had no estimate-wide number at all. The panel is on the ROUTE, not in a method module, so the two methods cannot drift; it renders for drafts and submitted versions alike and is deliberately **not** `position: sticky` (the editors below it are `svelte-dnd-action` drop zones whose geometry the library measures at drag start).

The figures are **computed by the domain**, never summed in Svelte: `EstimationTotals` + `EstimationVersion.totals()` in `src/domain/.../model/EstimationTotals.kt`. `totals()` is a **member** function, not an extension — `@JsExport` does not export extension functions, so an extension would compile, pass `:domain:build`, and then be missing from `domain.d.mts`. It must be called on the result of `calculate()` (a leaf's `cost`/`offerPrice` derive from the `CalculationParameters` that `calculate()` stamps on), and it reads `offerPT` off the already-computed `totalEffort` rather than re-summing. `totalOfferPrice` follows the customer's canonical formula — `(developmentCost + additionalOneTime + additionalRecurring) × (1 + salesSurcharge)`, the one `ExcelExporter.writePhases` applies per phase — while the separate `developmentOfferPrice` is the tree's own price EXCLUDING additional costs, which is what a column of per-leaf offer prices sums to. A RECURRING additional cost with a null phase contributes 0 and is counted in `recurringWithoutPhase`, which the panel surfaces as a warning line rather than silently absorbing (the task-138 lesson).

`EstimationGrid`'s footer reads those same totals. It used to reduce `Array.from(calcMap.values())`, but that map holds an entry for **every node including GROUPs** and a group accumulates its whole subtree — so the PERT footer **double-counted every grouped estimation**. Its `min`/`expected`/`max` sums stay leaf-based via `allLeaves(roots)` (those were always correct). `e2e/summary-panel.test.ts` pins both halves.

## Hours vs person-days (task-213)

Accompanying work (`TIME_RELATIVE`) is entered in **hours per week**; everything else in person-days. Both editors mark the hour values — the three effort inputs and, in the PERT grid, the PERT cell, read-only spans included — with `italic`, `data-unit="hours"` and the `grid.hoursPerWeekTitle` tooltip; person-day values keep the normal font. The marking is conditional on the row type (`isHours(node)`), so one input serves both kinds.

Which hours per working day a version is calculated with comes from ONE helper, `calculationHoursPerDay(version, system.hoursPerDay)` in `adapter.ts`, used by both the version editor and the schedule route: a draft follows the tenant setting; a submitted version uses the value it was submitted with; a version submitted before the conversion (`hoursPerDay: null`) uses **1**, because its stored numbers counted hours as person-days and 1 reproduces exactly those. Never pass the tenant setting for a submitted version — the browser recalculates every version from its tree, so that would quietly change numbers that were frozen at submit. The summary panel states the basis (`version-summary.hours-per-day`) when the version has accompanying work, and the admin page sets it (`system.hours-per-day`); `e2e/hours-per-day.test.ts` restores 8 after each test because the setting is global.

## Project list: "Only my projects" (task-200)

The project list filters to the current user's projects **by default** (`projects.only-mine`, loading `GET /api/projects?owner=me`); turning it off sets `?scope=all` in the page URL, so a reload or a shared link keeps the full list. The filter runs on the server, not in the store. With the filter on and nothing owned, the list shows its own empty state with `projects.show-all` — viewers, who cannot create projects, start there. Whether the change-owner button appears on the detail page is the backend's `canChangeOwner` flag (owner or ADMIN), never a client-side role check; `ChangeOwnerDialog` offers every user from `GET /api/users`, which lists only people who have already used Pythia (JIT provisioning).

## The one app header (`AppHeader`)

`src/frontend/src/lib/components/AppHeader.svelte` is the **single** top navigation, rendered by the root `+layout.svelte` on **every** route (task-141). Before it there were two divergent top bars — the root layout's inline header, hidden for `/sessions` via an `isSessionRoute` guard, and the session group's own chrome — so a user in a session room saw unfamiliar chrome with no recognisable way out. **Do not duplicate header markup into a route layout again**; add a destination to the component's `items` array instead. It renders the brand lockup (mark + wordmark, linking home), the horizontal menu, and `UserMenu`, above the brand gradient hairline; when `account` is `null` (the auth gate is showing the login dialog) only the lockup and hairline render.

The menu is a **flat row of `<a>`s inside a `<nav>`** — deliberately not a `<ul>`/`<li>` list, because `e2e/undo.test.ts` asserts a page-global `ul li` count of 0 and a nav list silently breaks it. A destination is active when the path equals its href **or starts with `href + '/'`**, so `/projects/{id}` keeps "Projects" marked and a room keeps "Sessions"; the active item gets `aria-current="page"` plus brand-green text and bottom border. `/estimations/**` sits under neither item and matches none — that is correct, not a gap. Each item's href comes from `resolve()` in the `items` array, which the `svelte/no-navigation-without-resolve` ESLint rule cannot follow, so the loop carries the same scoped `eslint-disable-next-line` the two computed-href call sites already use (`estimations/[id]/+page.svelte`, `VersionList.svelte`) — and the `<a href={item.href}` must stay on ONE line or the suppression lands on the wrong line. The per-page contextual back links (`project.pageBack`, `estimation.pageBack`, `compare.back`, `editor.back`, `session.summary.backToDraft`, `session.room.backToEstimation`) are unaffected: the menu is global navigation, they are local. `e2e/navigation.test.ts` pins the header on every route including a seeded session room, the active-item marking, and the way back out.

## System settings (name + custom stylesheet)

The installation's display name and optional stylesheet (task-146) come from `GET /api/system`, which is unauthenticated so the login screen can be branded before an account exists. `$lib/stores/system.svelte.ts` loads it once from the root layout; the load is deliberately **not** awaited into the auth path and its failure only `log.error`s — branding must never gate rendering.

The name is a **fallback chain, not a replacement**: `system.displayName ?? $_('brand.name')` in `AppHeader.svelte`, and `?? $_('brand.logoAlt')` for the standalone mark in `DevLoginDialog.svelte`. Keep the `brand.*` keys in both catalogs.

The custom stylesheet is delivered as `<link rel="stylesheet" href="/api/system/css">` in the root layout's `<svelte:head>`, LAST so it overrides `app.css` (which defines `--color-brand-green`, `--color-brand-green-light`, `--gradient-brand`). It is deliberately **not** injected as `<style>{cssText}</style>`: a `</style>` sequence in an uploaded file would close the element early and inject arbitrary markup. The `<link>` carries no `Authorization` header, which is exactly why the endpoint is `@PermitAll` — this is NOT a violation of the "downloads go through `apiFetch`" rule, which targets authenticated downloads that silently save a 401 body. Because the stylesheet lives in the document head, the admin page does a full `window.location.reload()` after an upload or removal rather than trying to swap it in place.
