# i18n and formatting

Loads when working under `src/frontend/src/lib/i18n/`. The frontend-wide rules are in `src/frontend/CLAUDE.md` and the root `CLAUDE.md`'s "Frontend hard rules".

## i18n (UI strings)

Frontend UI strings live in `svelte-i18n` JSON catalogs under `src/frontend/src/lib/i18n/` — **never** inline string literals in components (phase-16, task-124). `src/lib/i18n/index.ts` registers the `de` locale from `de.json`, calls `init({ fallbackLocale: 'de', initialLocale: 'de' })`, and exports `setUserLanguage(lang: SupportedLanguage)` (it drives the `locale` store off the domain enum's `code` — the same `SupportedLanguage` shared with the backend). The init runs as an import side effect; `src/routes/+layout.ts` imports it and its `load` does `await waitLocale()` so first paint never flashes a raw key (the route is `ssr = false`). Components render via the reactive `$_('key')` store (`import { _ } from 'svelte-i18n'`), with interpolation `$_('key', { values: { … } })` and ICU plural/select supported; a module-context helper (e.g. `UndoHistoryPanel.relativeTime`) reads it imperatively with `get(_)`. Keys are dot-separated and component-scoped (`panel.parameters.title`, `history.conflict.body`, `editor.undoTooltip`). task-124 was a DE lift-and-shift (catalog holds the current verbatim text — mostly English today with German pockets — so there was no visible change). task-125 added `en.json` (mirrors `de.json` key-for-key), registered `'en'`, and a **language switcher** in `UserMenu.svelte` — a DE/EN `<select>` that `PUT`s `/api/auth/me/language` via `apiFetch` then `setUserLanguage(...)`, surfacing failures through a local `ErrorBanner` + `log.error`. On startup the root layout reads the account's persisted `language` (from `GET /api/auth/me`; task-123's `CurrentUserDto.language`) and applies it once the account resolves, **falling back to `'de'`**. Both providers populate `AuthAccount.language` from the backend: Entra via `fetchCurrentUserAccount`, and the **dev** provider's `loadAccount()` also fetches `GET /api/auth/me` for the `language` only (roles/displayName stay client-side per task-120), so a language switch **persists across a dev reload** too (task-127). Its e2e (`e2e/language.test.ts`) proves the reload-persistence as `dev-estimator` (shared with the session/undo specs, not dedicated). The e2e run's language is NOT set by a browser locale — Accept-Language only seeds a user on first sighting — but pinned server-side by `e2e/global-setup.ts` to `E2E_LANG` (task-190). Code↔enum mapping is `SupportedLanguage.values().find((v) => v.code === code)` (the domain `fromCode` helper is JVM-only, not `@JsExport`ed). The generic `treetable/TreeTable.svelte` and the `dev/tree-table-demo` fixture are intentionally left un-internationalised (generic / dev-only).

All number/currency/date **formatting** goes through the single leaf module `src/frontend/src/lib/format.ts` (phase-16, task-126): `formatNumber` / `formatFixed(value, locale, fractionDigits)` / `formatCurrency` / `formatDate`, built on `Intl.NumberFormat` / `Intl.DateTimeFormat`. It is pure — the active locale is a **parameter** (callers pass `$locale ?? DEFAULT_LOCALE`, so the module never imports the i18n store and stays a leaf dependency; use `$locale` in markup, `get(locale)` in plain functions). **Never** call `.toFixed()`, `toLocale*()`, or hardcode a `de-DE` locale in a component — those were all migrated to the helper so English users see English grouping/date order. Currency is **always EUR/€** regardless of locale (the tool is EUR-only); cost/price columns that already carry a `(EUR)` header use `formatNumber`/`formatFixed` (grouping only), not `formatCurrency`. The `dev/tree-table-demo` fixture is exempt.
